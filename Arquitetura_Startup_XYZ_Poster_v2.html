Gestão de Documentos para IA Serverless Segura Escalável Otimizada em Custo
Infraestrutura serverless para receber, isolar, proteger e preservar documentos. O arquivo trafega direto para o S3 por URL pré-assinada, e o ciclo de vida do dado reduz o custo do histórico sem apagá-lo.
1
Login. O usuário autentica no Cognito e recebe o JWT.
2
Pedido. App chama a API com o JWT; o authorizer valida.
3
Autorização. Lambda lê o sub do token, nunca do corpo.
4
Credencial escopada. STS entrega acesso só ao prefixo do usuário.
5
URL devolvida. A API responde com a URL, válida por até 15 min.
6
Transferência direta. O cliente envia ou baixa direto do S3.
1
Fluxo da Requisição
1
Autenticação

Login no Cognito (OIDC). O token traz o sub, que identifica o usuário.

2
Requisição ao API Gateway

O app pede upload ou download. O JWT authorizer rejeita token inválido ou expirado antes de chamar a Lambda.

3
Autorização na Lambda

Define o prefixo usuario-{sub}/ a partir do token e gera o nome do objeto (UUID).

4
Credencial escopada

AssumeRole com session policy limitada ao prefixo; a URL é assinada com essa credencial.

5
Transferência direta

O cliente usa a URL no S3. Lambda (6 MB) e API Gateway (10 MB) têm limite de payload, por isso o arquivo não passa por eles.

6
Armazenamento e ciclo de vida

Objeto cifrado com SSE-KMS. Após 365 dias a storage class muda para Deep Archive.

👤

Lambda
  • Prefixo vem do token, nunca do input do cliente
  • AssumeRole com session policy por requisição

S3
  • Bucket privado, Block Public Access, Bucket Keys
  • Bucket policy nega tráfego sem TLS e PUT sem SSE-KMS

Por que essa Escolha
EC2 fixo→Serverless

Ingestão variável (~50 mil/mês). O custo acompanha o uso, sem servidor ocioso.

Lambda Function URL→API Gateway

Authorizer JWT, throttling e domínio próprio, com contrato de API desacoplado.

EFS / FSx→S3

Objetos imutáveis, 11 noves de durabilidade e classes de custo para arquivo.

SSE-S3→SSE-KMS

Controle da chave, trilha no CloudTrail e possibilidade de revogar. Não é exigência da LGPD, é uma boa prática de governança.

1 bucket por cliente→1 bucket + prefixo

Uma política, um lifecycle e uma chave para todos. Escala sem multiplicar recursos.

Glacier Instant→Deep Archive

Após 12 meses o dado vira retenção, sem SLA de minutos. Menor custo por GB.

5
Isolamento por Credencial, não por Convenção

O risco no desenho simples: uma Lambda com role que acessa o bucket inteiro e escolhe o prefixo no código. Um bug de autorização (IDOR, path traversal) e o usuário A lê os arquivos do usuário B.

A solução: a cada requisição a Lambda chama sts:AssumeRole passando uma session policy restrita ao prefixo do usuário. A permissão efetiva é a interseção da role com a session policy, e a URL é assinada com essa credencial temporária. Mesmo com bug, ela não alcança outro prefixo, e expira junto com a sessão (mínimo de 15 min).

{ "Effect": "Allow",
  "Action": ["s3:GetObject", "s3:PutObject"],
  "Resource": "arn:aws:s3:::xyz-docs/usuario-123/*" }
// + kms:GenerateDataKey e kms:Decrypt na chave do bucket
Detalhe técnico: a condition key s3:prefix vale só para ListBucket. Para Get e Put, a restrição vai no ARN do recurso, como acima.
Para escalar: ABAC com session tags (aws:PrincipalTag) permite uma única policy com o prefixo montado a partir da tag do usuário.

Estrutura de Objetos e Upload Seguro
usuario-123/
  └─ 2026/
     ├─ 7f3a91c2-….pdf
     └─ b20e4d18-….png
usuario-456/
  └─ 2026/ …

O prefixo faz parte da estratégia de isolamento. O nome do arquivo é um UUID gerado no servidor, e o nome original fica em metadata, evitando colisão e nomes maliciosos.

  • Presigned POST com content-length-range
  • Chave limitada por starts-with ao prefixo
  • Content-Type validado na policy do POST
  • CORS restrito ao domínio do app
  • Novo objeto escaneado pelo GuardDuty e etiquetado

Lifecycle: a Equação Financeira
FaseClasseCustoAcesso
0–365 diasS3 StandardBaseMilissegundos
365+ diasDeep Archive≈ 4–5% do StandardRestore: ~12 h (padrão), até 48 h (bulk)
  • Deep Archive tem retenção mínima de 180 dias e cobra restore e requests.
  • Objetos menores que 128 KB não transicionam por padrão.
  • Transição custa cerca de US$ 0,05 por mil objetos; 50 mil por mês dão ordem de US$ 2,50.
  • Versões não correntes expiram (ex.: 90 dias) e multipart incompleto é abortado em 7 dias.
Ressalva para IA: se o treino de modelos ler o histórico com frequência, use Glacier Instant Retrieval, ou planeje restores em lote com S3 Batch Operations.
8
Resiliência e Recuperação
🏢
Multi-AZ gerenciado
  • S3 Standard replica em 3 ou mais AZs (11 noves de durabilidade)
  • API Gateway, Lambda, Cognito e KMS são regionais e multi-AZ, sem instância para cair
⚙️
Se algo falhar
  • Throttling (429): retry com backoff no cliente
  • URL expirada: o app pede uma nova
  • Sobrescrita ou exclusão: versioning restaura
⏱️
Metas
  • RPO próximo de zero nos dados
  • RTO imediato no Standard; horas no Deep Archive
  • Falha de região não é coberta hoje; evolução: replicação entre regiões e IaC para recriar a stack

Evolução e Visão de Futuro
🔒 Imutabilidade

S3 Object Lock com retenção, se o histórico precisar ser à prova de exclusão por administrador.

🌍 Multi-região

Replicação entre regiões (CRR) para resistir à falha de uma região inteira.

🧱 IaC e CI/CD

Terraform ou CDK com pipeline no GitHub Actions. Ambiente recriável do zero.

📈 Observabilidade

Dashboard no CloudWatch, alarmes de erro e throttle, S3 Storage Lens.

💸 Custo

Intelligent-Tiering, S3 Inventory e restore em lote para treino de IA.

🛡️ Privacidade

Amazon Macie para achar dados pessoais e ambiente separado para treino, com dados anonimizados.
